Ce que la maquette engage côté code

Trois pièges déjà repérés dans le moteur

  • La cible n'est pas neutralisée en manuel. construire_rampe l'ignore, mais allouer s'en sert toujours : quotas_par_pa(cible + préservées) pilote la répartition entre plateformes. La griser serait donc faux — d'où la note explicite dans le panneau plutôt qu'un champ désactivé.
  • Le pilote, lui, n'a aucun effet en manuel (le code retourne avant niveau_pilote). Pire : rampe_pilote_infaisable reste appelé et peut cracher « la cible est trop basse pour tenir V comptes par run » à propos d'un pilote qui ne s'applique pas. La maquette le retire donc de l'écran en manuel — et le JS devra forcer pilote: null, pas seulement masquer le bloc.
  • Un run absent de la map vaut 0, sans un mot. Les champs doivent donc couvrir tous les runs retenus, et un run nouvellement retenu (MEP déplacée, exclusion décochée) doit apparaître dans la liste, à 0 mais visible.

Ce que la bascule vers « manuelle » doit faire

Pré-remplir les champs avec les volumes actuellement affichés, ceux de la forme qu'on quitte. Repartir de zéro obligerait à tout ressaisir alors que le geste réel est « je prends ma rampe linéaire et j'ajuste deux runs ». C'est aussi ce qui rend inutile un bouton « répartir » : on choisit la forme, on bascule, on retouche.

Le code mort à retirer au passage

app.js:1214 porte déjà if (forme === "manuelle") rampe.volumes = {} — jamais atteint faute d'option dans le sélecteur, et il enverrait une map vide, donc tous les runs à 0.

Questions ouvertes — à trancher avant le code

  • Variante A ou B ? A est plus sûre et conforme au layout ; B est plus agréable mais demande de protéger la saisie du re-rendu.
  • L'aperçu en barres, maintenant ou plus tard ? Il est indépendant de la rampe manuelle et sert aussi aux trois autres formes.
  • Le dépassement de stock doit-il alerter ? Ici il borde d'ambre. Ce n'est pas une erreur — le surplus part en report — mais c'est utile à voir avant de générer.
  • Faut-il persister les volumes manuels dans PlanParams comme le reste ? Le YAML les porte déjà (Forme::Manuelle est sérialisée), donc oui par défaut, mais cela veut dire qu'un plan rechargé rouvre en manuel avec ses volumes.
