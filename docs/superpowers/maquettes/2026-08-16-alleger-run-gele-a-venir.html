Exclure un run à venir d'une MEP gelée

Maquette du 16/08/2026 — ce qui change dans la modale « Alléger le run », pour validation avant code UI. Un run à venir dont la MEP est déjà gelée ❄ (fichier déjà transmis) peut désormais être exclu en bloc, comme un run déjà joué. La bascule à deux segments gagne un troisième segment « Exclure le run », dont le corps reprend mot pour mot celui du run passé — à une différence près : le motif pré-rempli dit « exclu » et non « exclu a posteriori », puisque le run n'a pas encore été joué. Rien d'autre ne change : le run passé garde son mode unique, et le run à venir d'une MEP future garde ses deux segments actuels (état B, en regard).

État A (nouveau) — run à venir, MEP gelée

RF03 est programmé au 20/09/2026, mais sa MEP du 01/08/2026 est déjà gelée : le fichier destiné à la plateforme est déjà parti. La bascule affiche donc trois segments ; l'utilisateur a choisi le troisième.

Alléger le run RF03

RF03 Run du 20/09/2026 MEP gelée ❄ 01/08/2026 14 comptes actifs
Exclure le run — les 14 lignes actives du run sont retirées du plan, épinglées comprises.

Les lignes restent consultables via le filtre « retiré » et ne seront pas replacées par une régénération. Le retrait est annulable.

⚠ 14 compte(s) appartiennent à une MEP gelée (01/08/2026). Son fichier a déjà été transmis : il changera au prochain tirage.

Même règle qu'un run passé : le bouton reste inerte tant que rien n'est écrit après le tiret — le motif pré-rempli dit quel run est exclu, jamais pourquoi. Seul change le verbe : « exclu », sans « a posteriori », parce que le run n'a pas encore été joué — la MEP gelée le rend seulement impossible à alléger autrement sans casser un fichier déjà transmis.

État B (inchangé) — run à venir, MEP future

Pour contraste : même écran, mais la MEP de ce run n'est pas encore gelée. La bascule garde ses deux segments actuels ; version compacte du mode proportionnel.

Alléger le run RF14

RF14 Run du 29/09/2026 28 comptes actifs
compte(s) sur 28 actifs

La part de chaque plateforme dans le run est conservée. Une plateforme n'est jamais vidée : son dernier compte actif reste.

6 seront retiré(s) — 22 resteront actifs sur ce run

Ce run n'a pas de MEP gelée : rien ne l'empêche d'être allégé finement, donc le troisième segment n'est pas offert. C'est la MEP, jamais la date du run seule, qui décide de l'apparition du segment « Exclure le run » sur un run à venir.

Ce qui décide de l'offre des trois segments

Résumé des trois états possibles de la modale :

  • run passé → mode unique « Exclure le run » (inchangé, pas de bascule) ;
  • run à venir, MEP future → bascule à deux segments (inchangé, état B) ;
  • run à venir, MEP déjà gelée ❄ → bascule à trois segments, le troisième reprenant le corps du run passé avec un motif pré-rempli « exclu » — sans « a posteriori » (état A, nouveau).
L'avertissement ⚠ MEP gelée existant est repris sans changement de forme : il apparaît déjà aujourd'hui sous les deux autres modes lorsque des comptes concernés sont sélectionnés.
