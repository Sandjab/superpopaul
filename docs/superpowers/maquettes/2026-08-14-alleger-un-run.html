Alléger un run

Maquette du 14/08/2026 — trois aides à la saisie des retraits en lot. Le geste part de la ligne du run dans la timeline (onglet Paramétrage), à côté de « + Ajouter ». Tout aboutit au retrait existant : les aides ne font que calculer une liste de CF, la trace (date + motif) et sa documentation par le rapport ne changent pas.

0 · Le déclencheur, sur la ligne du run

Rien d'autre ne bouge dans la timeline. Le bouton apparaît là où se prend la décision — « alléger », c'est une décision sur un run, pas sur une sélection du récap.

1 · Run passé — exclure le run

Le run a été joué sans ses comptes : la décision vécue est « exclure le run a posteriori ». Un seul mode est offert, et il porte sur toutes les lignes actives du run, épinglées comprises — exclure un run, c'est tout le run.

Le bouton est inerte alors que le champ n'est pas vide : le motif pré-rempli dit quel run est exclu, jamais pourquoi. Tant que le texte est resté celui proposé, il n'y a pas de cause — et c'est la cause que le rapport transmettra au destinataire, six mois plus tard. Le bouton s'active dès qu'une suite est écrite après le tiret.

2 · Run à venir — retirer N, répartition des plateformes conservée

Le volume du run est revu à la baisse. On dit combien retirer, l'application propose qui, et la proposition est amendable compte par compte avant d'être appliquée. La modale est large (variante modal-wide de la fenêtre d'ajout) : elle liste des comptes.

Ce que la proposition garantit, et qui se lit sur l'écran :

  • la part de chaque plateforme est conservée (les N sont répartis aux plus forts restes, comme les quotas de la génération) ;
  • une plateforme n'est jamais vidée : la couverture gagnée à la génération ne se perd pas par décimage — c'est le candidat grisé du panneau d'échange ;
  • les lignes épinglées (ajoutées à la main, ou placées pour la couverture) ne sortent qu'en dernier recours ; elles restent proposables à l'échange, ce qui est un choix explicite de l'utilisateur, pas une décision de l'application ;
  • dans une plateforme, sortent d'abord les comptes hors annuaire, puis les résolutions les plus anciennes — l'inverse de l'ordre d'allocation.
Si N est trop grand (planchers atteints, ou N ≥ actifs du run), la proposition n'est pas rendue : un message dit le maximum retirable. Vider un run se fait avec « Exclure le run », qui n'est offert que pour un run passé.

Le pied est permanent : il affiche les deux nombres dès l'ouverture, avant toute case cochée (« 0 gardé(s) — 7 seront retiré(s) »), et suit chaque clic. On coche ce qu'on garde parce que c'est ce que la décision énonce (« il ne reste que les pilotes ») et parce que c'est le plus petit nombre de clics dans le cas visé. Tout cocher rend le bouton inerte : « Retirer 0 compte(s) » n'est pas un geste. Un run passé n'offre pas ce mode.

4 · Ce qui ne change pas

Un geste = un seul retrait, quel que soit le mode : une date, un motif, une écriture. C'est ce qui permet au rapport de rapprochement de regrouper les comptes sous un chapeau au lieu de répéter 143 fois la même phrase (maquette 2026-08-14-rapport-gestes-groupes.html). Le retrait ligne à ligne du récap, l'avertissement de MEP gelée et la réactivation restent tels quels.

Limite dite comme telle : ces aides retirent des comptes du plan courant, elles ne touchent pas la rampe. Une régénération replacera d'autres comptes pour tenir le volume des runs — les retirés, eux, ne reviennent jamais.
