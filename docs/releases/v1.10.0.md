## Un retrait ne se remplace plus

Alléger un run réduisait le plan… jusqu'au calcul suivant. La place libérée par
un compte retiré restait comptée dans la cible : au prochain aperçu ou à la
prochaine régénération, la rampe tirait d'autres comptes pour combler le volume,
et l'allègement se défaisait en silence.

Un retrait est désormais définitif dans les comptes : la place d'un compte
retiré reste la sienne, personne ne la prend. Alléger un run de vingt comptes,
c'est un plan plus léger de vingt comptes — à l'écran, dans les fichiers, et
après n'importe quelle régénération. Pour récupérer ce volume, deux gestes
explicites et deux seuls : réactiver les comptes, ou augmenter la cible.

## Exclure un run à venir d'une mise en production gelée

Un run pas encore joué mais rattaché à une mise en production déjà passée était
dans une impasse : ses lignes gelées survivent à tout — à la régénération comme
à la case « exclure » du paramétrage — et la fenêtre « Alléger… » interdisait
de le vider, son exclusion n'étant offerte qu'aux runs déjà joués.

La fenêtre propose maintenant « Exclure le run » pour ces runs-là aussi, en
troisième position à côté des deux modes d'allègement. Le motif est pré-rempli
avec le run et sa date — sans le « a posteriori » réservé aux runs joués,
puisque celui-ci ne l'a pas encore été — et, comme toujours, le bouton reste
inerte tant que la cause n'est pas écrite après le tiret.

Rien ne change pour les autres runs : un run joué s'exclut comme avant, et un
run à venir d'une mise en production future se décime ou se réduit à une
sélection, mais ne se vide pas — le vider n'aurait pas de sens tant que la
régénération peut replacer ses comptes ailleurs.

## L'aperçu suit le geste

Après un allègement, une exclusion, un ajout, un déplacement ou une
réactivation, l'onglet Paramétrage continuait d'afficher les chiffres d'avant —
Visé, Stock, Placé, Reliquat décrivaient un plan qui n'existait plus, jusqu'à ce
qu'une saisie quelconque relance le calcul.

Chaque retouche réussie recalcule maintenant l'aperçu, en même temps qu'elle
recharge le récapitulatif. Ce que la timeline affiche est le plan tel qu'il
vient d'être écrit.

## Le rapport du plan reste à jour

Le rapport HTML du plan n'était produit que par son bouton : sitôt le plan
retouché ou régénéré, le document sur disque décrivait un plan périmé — prêt à
être transmis par erreur.

Il rejoint désormais les livrables : chaque génération et chaque retouche le
réécrivent, avec les fichiers par mise en production et le classeur. Le bouton
« Rapport du plan… » ne change pas ; il régénère et ouvre le document, comme
avant.

## Bon à savoir

La case « exclure » de la timeline du paramétrage garde son rôle : elle écarte
un run du calcul, elle ne retouche pas le plan enregistré. Pour retirer
réellement les comptes d'un run — gelé ou joué — le geste est « Alléger… » sur
la ligne du run.
